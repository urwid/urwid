List-like List Walkers¶

class urwid.SimpleFocusListWalker(contents: Iterable[_T], wrap_around: bool = False, *, follow_end: bool = False)¶

ListWalker like SimpleListWalker that also keeps focus tracking items across edits.

Initialize a list walker, which can be treated as a list since it inherits MonitoredList.

Changes made to this object (when it is treated as a list) are detected automatically and will cause ListBox objects using this list walker to be updated.

Also, items added or removed before the widget in focus with normal list methods will cause the focus to be updated intelligently.

Parameters:

  • contents – list to copy into this object

  • wrap_around – if true, jumps to beginning/end of list on move

  • follow_end – if true, items added after a focused last item take the focus, so a ListBox showing a growing log keeps showing its newest line until the user moves the focus up; see MonitoredFocusList.follow_end

Raises:

ListWalkerError – contents is not iterable.

Deque-like List Walkers¶

class urwid.SimpleFocusDequeWalker(contents: Iterable[_T], wrap_around: bool = False, maxlen: int | None = None, *, follow_end: bool = False)¶

A ListWalker backed by a MonitoredFocusDeque.

Mirrors SimpleFocusListWalker method-for-method, adapted to deque’s narrower API. See the performance caveat documented on SimpleDequeWalker – it applies equally here.

Build the walker, wrapping contents in a focus-tracking deque.

This class inherits MonitoredFocusDeque, which means it can be treated as a deque.

Changes made to this object (when it is treated as a deque) are detected automatically and will cause ListBox objects using this list walker to be updated.

Also, items added or removed before the widget in focus with normal deque methods – including eviction caused by maxlen – will cause the focus to be updated intelligently.

Parameters:

  • contents – iterable to copy into this object

  • wrap_around – if true, jumps to beginning/end of deque on move

  • maxlen – if set, bounds the deque’s length; the oldest items are silently evicted from the opposite end once full, and focus is adjusted to keep tracking a sensible item (see MonitoredFocusDeque)

  • follow_end – if true, items added after a focused last item take the focus, so a ListBox showing a growing log keeps showing its newest line until the user moves the focus up; see MonitoredFocusDeque.follow_end

Raises:

ListWalkerError – contents is not iterable.

class urwid.SimpleDequeWalker(contents: Iterable[_T], wrap_around: bool = False, maxlen: int | None = None)¶

A ListWalker backed by a MonitoredDeque.

Mirrors SimpleListWalker method-for-method, adapted to deque’s narrower API (in particular, maxlen-bounded eviction).

Note

ListWalker.get_focus()/ListWalker.get_next()/ListWalker.get_prev() (inherited, unmodified) index via self[position], and deque.__getitem__ is O(n) (linked-block structure) rather than a list’s O(1) – worth bearing in mind for a very large unbounded deque, though the bounded/maxlen scrollback use case this class targets is small enough that it does not matter in practice. No caching layer is provided.

Initialize a deque walker, which can be treated as a deque since it inherits MonitoredDeque.

Changes made to this object (when it is treated as a deque) are detected automatically and will cause ListBox objects using this list walker to be updated.

Parameters:

  • contents – iterable to copy into this object

  • wrap_around – if true, jumps to beginning/end of deque on move

  • maxlen – if set, bounds the deque’s length; the oldest items are silently evicted from the opposite end once full

Raises:

ListWalkerError – contents is not iterable.

Return self.

Provides compatibility with old SimpleListWalker class.

Filtering List Walkers¶

class urwid.FilteredListWalker(source: ListWalker[int, _T] | Iterable[_T], *, predicate: Callable[[_T], bool] | None = None, wrap_around: bool = False)¶

A read-only view of a source list walker that shows only the items passing a predicate.

The positions of the view are the indices of the source, so a position taken from the view addresses the same item in source, and no mapping between two index spaces is needed. Items are added, removed and moved through source; the view has no methods that change the list. Every "modified" signal of the source re-applies the predicate, and the view emits its own "modified" once per such rebuild. That includes the signal the source’s own set_focus() emits; the view never changes the focus of the source.

The focus of the view stays on the same widget while that widget passes the predicate. When it does not:

  • after a change to the source, or refilter(), the focus moves to the next visible item at or after the old focus position, else to the last visible item;

  • after a change of the predicate, the focus moves to the first visible item.

An empty view has no focus. When the widget focused last becomes visible again, it takes the focus back.

A predicate that raises leaves the view as it was, except after a change to the source: the old positions may no longer exist there, so the view empties itself, emits "modified", and the exception reaches the code that changed the source. The next change to the source or the predicate fills the view again.

A rebuild walks the source once, so it is linear in the length of a list or a deque source. Reading one item or the focus indexes the source, which is linear for a deque, as SimpleDequeWalker notes.

>>> import urwid
>>> words = ("apple", "pear", "plum", "peach", "fig", "lime")
>>> view = urwid.FilteredListWalker([urwid.Text(word) for word in words])
>>> view.set_focus(2)
>>> list(view.positions())
[0, 1, 2, 3, 4, 5]
>>> view.set_predicate(lambda widget: widget.text.startswith("pe"))
>>> list(view.positions())
[1, 3]
>>> widget, position = view.get_focus()
>>> widget.text, position
('pear', 1)

Create a view of source that shows the items for which predicate returns true.

Parameters:

  • source – a list walker that is also a sequence, such as SimpleFocusListWalker, SimpleFocusDequeWalker or their non-focus variants. Any other iterable of widgets is copied into a new SimpleFocusListWalker.

  • predicate – called with each widget of the source; None shows every widget.

  • wrap_around – if true, moving past one end of the visible items continues at the other end.

Raises:

  • TypeError – source is a list walker that is not a sequence, such as a TreeWalker.

  • ListWalkerError – source is not iterable.

  • Exception – whatever predicate raises for a widget of source.

class urwid.TreeNode(value: _T, parent: ParentNode[Any] | None = None, key: Hashable = None, depth: int | None = None)¶

Store tree contents and cache TreeWidget objects.

A TreeNode consists of the following elements: * key: accessor token for parent nodes * value: subclass-specific data * parent: a TreeNode which contains a pointer back to this object * widget: The widget used to render the object

Store value under key, with parent and depth as given, or computed from parent when omitted.

change_key(key: Hashable) → None¶

Rename this node to key, updating the parent’s reference to it as well.

Raises:

TreeWidgetError – this node is the root. The parent is not loaded yet and load_parent() is not overridden. key is already a key among the parent’s children, this node’s own key included.

get_depth() → int¶

Return this node’s depth in the tree, computing and caching it if necessary.

The ancestors are walked in a loop rather than recursively, so the depth of the tree is not limited by the interpreter’s recursion limit. Every ancestor whose depth was unknown caches its own depth as well. The walk stops at an ancestor whose class overrides this method, and uses the depth that ancestor returns.

Raises:

TreeWidgetError – the parent links form a cycle.
