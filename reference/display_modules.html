property palette: Mapping[Hashable, PaletteEntrySpecs]¶

Return a read-only view of the registered palette entries.

The view follows later changes to the palette. Change the palette with register_palette() and register_palette_entry().

>>> from urwid.display.html_fragment import HtmlGenerator
>>> screen = HtmlGenerator()
>>> screen.register_palette_entry("title", "white", "dark blue")
>>> screen.palette["title"].basic
AttrSpec('white', 'dark blue')
Returns:

per entry name, the specifications it is drawn with; None names the default attribute.

register_palette(palette: Iterable[PaletteEntry], *, replace: bool = False) → None¶

Register a set of palette entries.

With replace, the entries that palette does not name are removed once all of its entries are registered. A removed name is drawn in the terminal’s default colors, as a name that was never registered is. The None entry is kept unless palette names it, so the screen keeps its default attribute.

>>> from urwid.display.html_fragment import HtmlGenerator
>>> screen = HtmlGenerator()
>>> screen.register_palette([("title", "white", "dark blue"), ("body", "black", "light gray")])
>>> screen.register_palette([("body", "white", "black")], replace=True)
>>> list(screen.palette)
[None, 'body']
Parameters:

  • palette – a list of (name, like_other_name) or (name, foreground, background, mono, foreground_high, background_high) tuples

  • replace – remove the entries that palette does not name

Raises:

ScreenError –

an entry is neither a 2-, 3-, 4- nor 6-tuple, or copies a name that is not registered yet. The entries before it stay registered, and with replace no entry is removed.

The (name, like_other_name) format will copy the settings from the palette entry like_other_name, which must appear before this tuple in the list.

The mono and foreground/background_high values are optional ie. the second tuple format may have 3, 4 or 6 values. See register_palette_entry() for a description of the tuple values.

resolve_attr(attr: Hashable, index: int) → AttrSpec¶

Return the AttrSpec to draw a canvas run with display attribute attr.

Starting from the palette entry of None, each layer of attr (a palette name, an AttrSpec or a LayeredAttr), outermost first, is placed over the result so far with AttrSpec.layered_over(). A name missing from the palette is drawn with ‘default’ colors, hiding the layers under it.

Parameters:

  • attr – display attribute of a canvas run

  • index – position in the palette entry tuple: 0 for 16 colors, 1 for monochrome, 2 for 88 colors, 3 for 256 colors, 4 for true color

Raises:

IndexError – index is outside 0-4 and a layer is a palette name.

class urwid.display.raw.Screen(input: SupportsFileno = <_io.TextIOWrapper name='<stdin>' mode='r' encoding='utf-8'>, output: TextWriter = <_io.TextIOWrapper name='<stdout>' mode='w' encoding='utf-8'>, bracketed_paste_mode: bool | None = None, focus_reporting: bool | None = None, extended_keys: bool = False)¶

Raw screen backend that drives a real POSIX terminal.

Initialize a screen that directly prints escape codes to an output terminal.

Parameters:

  • input – the terminal input, read through its file descriptor.

  • output – the terminal output, which the escape codes are written to.

  • bracketed_paste_mode – enable bracketed paste (begin/end paste keystrokes). None (default) auto-detects via DECRQM and enables it once confirmed supported; pass True/False to force it without probing.

  • focus_reporting – enable focus reporting (focus in/focus out keystrokes). None (default) auto-detects via DECRQM and enables it once confirmed supported; pass True/False to force it without probing.

  • extended_keys – report the keys the legacy encodings cannot tell apart, such as 'ctrl enter' and 'ctrl i' apart from 'tab', through the keyboard protocol the terminal supports. Ctrl+C and Ctrl+Z then arrive as keys instead of signals; see Extended Keys.

Note

on terminal-generated signals: putting the terminal into cbreak mode (see start()) does not clear the tty’s ISIG flag, so the line discipline still turns Ctrl+C and Ctrl+Z into SIGINT and SIGTSTP and delivers them to this process (urwid/urwid#1268). SIGINT is left for the application or its event loop to handle as it sees fit. SIGTSTP is handled by this class: signal_init() installs a handler that wakes the input loop, which restores the terminal before actually suspending the process, then puts the terminal back into cbreak/alternate-buffer mode and forces a redraw on resume, so a stray Ctrl+Z does not leave a stale, unresponsive frame painted on screen. The suspend therefore waits until the application next reads input, through get_input() or the callback hook_event_loop() registers. Applications that install their own SIGTSTP handler on top of this one should chain to the previous handler (as this class does) rather than replacing it outright, and multithreaded applications must call signal_init() and signal_restore() from the main thread, since only the main thread can receive process signals. start() also clears the IEXTEN flag, which cbreak mode leaves on, so on macOS and the BSDs Ctrl+V, Ctrl+O and Ctrl+Y reach the application instead of being handled by the terminal driver. It clears FLUSHO as well: a Ctrl+O typed before the start can leave that output discard on, and without IEXTEN no Ctrl+O can turn it off. stop() restores both flags.

get_input(raw_keys: Literal[False]) → _DecodedInput¶
get_input(raw_keys: Literal[True]) → tuple[_DecodedInput, list[int]]

Return pending input as a list.

Parameters:

raw_keys – return raw keycodes as well as translated versions

Raises:

RuntimeError – the screen has not been started.

This function will immediately return all the input since the last time it was called. If there is no input pending it will wait before returning an empty list. The wait time may be configured with the set_input_timeouts function.

If raw_keys is False (default) this function will return a list of keys pressed. If raw_keys is True this function will return a ( keys pressed, raw keycodes ) tuple instead.

Examples of keys returned:

  • ASCII printable characters: space, a, 0, A, -, /

  • ASCII control characters: tab, enter

  • Escape sequences: up, page up, home, insert, f1

  • Key combinations: shift f1, meta a, ctrl b

  • Window events: "window resize"

Other characters, decoded from the terminal encoding (UTF-8, or a single- or double-byte encoding):

  • Unicode characters: “u00a5”, “u253c”, “u4e2d”

Examples of mouse events returned:

  • Mouse button press: (‘mouse press’, 1, 15, 13),

    (‘meta mouse press’, 2, 17, 23)

  • Mouse button release: (‘mouse release’, 1, 18, 13),

    (‘ctrl mouse release’, 2, 17, 23)

The button number is a MouseButton value.

set_input_timeouts(max_wait: float | None = None, complete_wait: float = 0.1, resize_wait: float = 0.1) → None¶

Set the get_input timeout values.

All values have a granularity of 0.1s, ie. any value between 0.15 and 0.05 will be treated as 0.1 and any value less than 0.05 will be treated as 0. Waits longer than 25.5 seconds are split into multiple curses waits.

Parameters:

  • max_wait – amount of time in seconds to wait for input when there is no input pending, wait forever if None

  • complete_wait – amount of time in seconds to wait when get_input detects an incomplete escape sequence at the end of the available input

  • resize_wait – amount of time in seconds to wait for more input after receiving two screen resize requests in a row to stop urwid from consuming 100% cpu during a gradual window resize operation

set_mouse_tracking(enable: bool = True) → None¶

Enable mouse tracking.

After calling this function get_input will include mouse click events along with keystrokes.

Raises:

NotImplementedError – enable is false while tracking is on; tracking cannot be turned off.

WebSocket display¶

class urwid.display.websocket.Screen(transport: Transport, *, cols: int = 80, rows: int = 24)¶

Screen that draws into one browser page through a Transport.

It takes input only from feed(), so it needs no file descriptor, and it runs on any event loop. Input reaches the main loop through an alarm of the event loop, which is what makes the main loop redraw.

ExitMainLoop raised by an input handler ends this session only: the screen closes its transport. Any other exception from an input handler or a redraw, and ExitMainLoop from an alarm, stops the event loop, and with it every session it runs, unless the main loop runs on a GuardedEventLoop whose handler calls close().

Call every method from the thread that runs the event loop.

Important

Do not use paused() with this screen: there is no terminal to hand over.

Initialize an unstarted screen that sends through transport.

Parameters:

  • transport – the connection to the page.

  • cols – the width until the page reports its own; at most MAX_COLS is used.

  • rows – the height until the page reports its own; at most MAX_ROWS is used.

Raises:

ValueError – cols or rows is less than 1.

clear() → None¶

Force the screen to be completely repainted on the next call to draw_screen().

close() → None¶

End the session: drop the queued input, ignore further messages and close the transport.

property closed: bool¶

Return whether close() has ended the session.

draw_screen(size: tuple[int, int], canvas: Canvas) → None¶

Send the rows of canvas that the page does not show yet.

Nothing is sent once the session is closed.

Raises:

ValueError – canvas does not have the number of rows given by size.

feed(message: str | bytes) → None¶

Check one message from the page and queue the input it carries.

A message is a JSON object of one of these forms, with no other keys:

  • {"type": "key", "key": <name>}, where the name is an urwid key name the page script can send: a named key such as "page up" or "f5", or one character that is not a control character, after the modifiers "shift ", "meta " and "ctrl " in that order.

  • {"type": "resize", "cols": <int>, "rows": <int>} with both sizes at least 1. A size above MAX_COLS or MAX_ROWS is reduced to that limit.

Messages that arrive after close() are ignored.

Parameters:

message – the content of one WebSocket message.

Raises:

InvalidMessageError – the message is binary, longer than MAX_MESSAGE_LENGTH, not of one of the forms above, or more than MAX_PENDING_INPUT keys wait for the main loop.

urwid.display.html_fragment.screenshot_init(sizes: list[tuple[int, int]], keys: list[_DecodedInput]) → None¶

Replace display.curses.Screen and display.raw.Screen class with HtmlGenerator.

Call this function before executing an application that uses display.curses.Screen to have that code use HtmlGenerator instead.

Parameters:

  • keys – list of lists of keys to be returned by each call to HtmlGenerator.get_input()

  1. start in 80x25 with its first call to get_cols_rows()

  2. take a screenshot when it calls draw_screen(..)

  3. simulate 5 down keys from get_input()

  4. take a screenshot when it calls draw_screen(..)

  5. simulate keys a, b, c and a "window resize" event

  6. resize to 20x10 on its second call to get_cols_rows()

  7. take a screenshot when it calls draw_screen(..)

  8. simulate a “Q” keypress to quit the application

screenshot_init( [ (80,25), (20,10) ],

[ [“down”]*5, [“a”,”b”,”c”,”window resize”], [“Q”] ] )

get_input_nonblocking() → tuple[float | None, list[str], list[int]]¶

Return a (next_input_timeout, keys_pressed, raw_keycodes) tuple.

The protocol for our device requires waiting for acks between each command, so this method responds to those as well as key press and release events.

Key repeat events are simulated here as the device doesn’t send any for us.

raw_keycodes are the bytes of messages we received, which might not seem to have any correspondence to keys_pressed.

hook_event_loop(event_loop: EventLoop, callback: Callable[[list[str], list[int]], Any]) → None¶

Watch the serial device on event_loop and pass what get_input_nonblocking() returns to callback.

The device’s answers, an ACK or an error response, are answered with the next queued command as they arrive, and a held key is repeated from an alarm, since the device sends no repeats. A command whose ACK does not arrive within ACK_TIMEOUT seconds is sent again, up to ACK_RESENDS times, and then dropped, so the queue never stops.

Logged:

  • a warning when the device stops answering, and an info message when it answers again;

  • an error the first time the device refuses a command with a given code.

class urwid.display.lcd.KeyRepeatSimulator(repeat_delay: float, repeat_next: float)¶

Provide simulated repeat key events when given press and release events.

If two or more keys are pressed, disable repeating until all keys are released.

Deprecated since version 5.1.0: The LCD display module will be removed in version 6.0, with no replacement.

Set up the repeat timing.

Parameters:

  • repeat_delay – seconds to wait before starting to repeat keys

  • repeat_next – time between each repeated key

next_event() → tuple[float, str] | None¶

Return (remaining, key), or None if no events are pending.

remaining is the number of seconds (float) until the key repeat event should be sent.

press(key: str) → None¶

Record that key was pressed, disabling repeat if another key is already held down.

release(key: str) → None¶

Record that key was released, re-enabling repeat once no key is held down.

sent_event() → None¶

Call this method when a key repeat event was sent.

The timer will be reset for the next event.
