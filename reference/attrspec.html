Raw Display Attributes¶

class urwid.AttrSpec(fg: str = 'inherit', bg: str = 'inherit', colors: Literal[1, 16, 88, 256, 16777216] = 256, *, hyperlink: Hyperlink | str | None = None, underline_color: str | None = None)¶

Text attribute specification, encoding foreground and background colors and display settings.

Parameters:

  • fg –

    a string containing a comma-separated foreground color and settings

    Color values: ‘default’ (use the terminal’s default foreground), ‘inherit’ (take the color from the enclosing attribute, see layered_over()), ‘black’, ‘dark red’, ‘dark green’, ‘brown’, ‘dark blue’, ‘dark magenta’, ‘dark cyan’, ‘light gray’, ‘dark gray’, ‘light red’, ‘light green’, ‘yellow’, ‘light blue’, ‘light magenta’, ‘light cyan’, ‘white’

    High-color example values: ‘#009’ (0% red, 0% green, 60% red, like HTML colors) ‘#23facc’ (RRGGBB hex color code) ‘#fcc’ (100% red, 80% green, 80% blue) ‘g40’ (40% gray, decimal), ‘g#cc’ (80% gray, hex), ‘#000’, ‘g0’, ‘g#00’ (black), ‘#fff’, ‘g100’, ‘g#ff’ (white) ‘h8’ (color number 8), ‘h255’ (color number 255); with 2**24 colors ‘hN’ is kept as palette entry N, and the cube and gray forms are 24-bit colors

    Setting: ‘bold’, ‘italics’, ‘underline’, ‘blink’, ‘standout’, ‘strikethrough’, ‘faint’; with ‘no-’ in front (‘no-bold’) a setting is turned off rather than taken from the enclosing attribute; it is part of the attribute, so ‘red,no-bold’ and ‘red’ are unequal. ‘double underline’, ‘curly underline’, ‘dotted underline’ and ‘dashed underline’ are an underline in that style, which a terminal without underline styles draws as ‘underline’

    Some terminals use ‘bold’ for bright colors. Most terminals ignore the ‘blink’ setting. If the color is not given then ‘default’ will be assumed.

  • bg –

    a string containing the background color

    Color values: ‘default’ (use the terminal’s default background), ‘inherit’ (take the color from the enclosing attribute), ‘black’, ‘dark red’, ‘dark green’, ‘brown’, ‘dark blue’, ‘dark magenta’, ‘dark cyan’, ‘light gray’

    High-color exaples: see fg examples above

    An empty string will be treated the same as ‘default’.

  • colors –

    the maximum colors available for the specification

    Valid values include: 1, 16, 88, 256, and 2**24. High-color values are only usable with 88, 256, or 2**24 colors. With 1 color only the foreground settings may be used. Any display draws the result: a color it does not have is drawn as the nearest one it has.

  • hyperlink – the terminal hyperlink of the text, a string being its URI; None takes the link of the enclosing attribute, and NO_HYPERLINK hides it.

  • underline_color – the color of the underline, given as a background color is; None and ‘inherit’ take it from the enclosing attribute, and ‘default’ draws it in the text color. A terminal without underline colors draws it in the text color.

Raises:

  • AttrSpecError – colors is not a supported palette size. fg, bg or underline_color is invalid, or needs more colours than colors.

  • ValueError – hyperlink is a string that is not a valid Hyperlink URI.

>>> AttrSpec("dark red", "light gray", 16)
AttrSpec('dark red', 'light gray')
>>> AttrSpec("yellow, underline, bold", "dark blue")
AttrSpec('yellow,bold,underline', 'dark blue')
>>> AttrSpec("#ddb", "#004", 256)  # closest colors will be found
AttrSpec('#dda', '#006')
>>> AttrSpec("#ddb", "#004", 88)
AttrSpec('#ccc', '#000', colors=88)
>>> AttrSpec("inherit,bold", "dark blue")
AttrSpec('inherit,bold', 'dark blue')
>>> AttrSpec(hyperlink="https://urwid.org")
AttrSpec('inherit', 'inherit', hyperlink=Hyperlink(uri='https://urwid.org', id=''))
>>> AttrSpec("default,curly underline", "default", underline_color="light red")
AttrSpec('default,curly underline', 'default', underline_color='light red')

copy_modified(fg: str | None = None, bg: str | None = None, colors: Literal[1, 16, 88, 256, 16777216] | None = None, *, hyperlink: Hyperlink | str | Literal[_Keep.KEEP] | None = _Keep.KEEP, underline_color: str | Literal[_Keep.KEEP] | None = _Keep.KEEP) → Self¶

Return a new AttrSpec, replacing fg, bg, colors, hyperlink and/or underline_color.

Without colors, the result uses 88 colors or true color when this specification was made for them, else 256 colors, so a color can be added to a specification that has none. A given color is parsed in the color mode of the result. A color that is not given keeps its kind and number, a palette entry included. Only when colors names a mode that cannot hold it, it is converted as that mode parses its description: approximated at 256 and 88 colors, and an 88-color entry above 15 becomes its RGB value at true color. The hyperlink and the underline color are kept unless given; None makes the result take the enclosing one.

The result is built with this object’s class. The hyperlink and underline_color keywords are passed to its constructor only when the result has them, so a subclass whose constructor takes only fg, bg and colors works for every other change.

Raises:

  • AttrSpecError – colors is not a supported palette size, or fg, bg or underline_color is invalid or needs more colors than the result has. A kept color that colors cannot hold, such as a palette entry with 16 colors, raises as well.

  • ValueError – hyperlink is a string that is not a valid Hyperlink URI.

  • TypeError – the result has a link or an underline color, and the constructor of this object’s class does not accept it.

>>> AttrSpec("inherit,bold", "inherit").copy_modified(bg="dark blue")
AttrSpec('inherit,bold', 'dark blue')
>>> AttrSpec(hyperlink="https://urwid.org").copy_modified(hyperlink=None)
AttrSpec('inherit', 'inherit')

get_rgb_values() → tuple[int | None, int | None, int | None, int | None, int | None, int | None]¶

Return (fg_red, fg_green, fg_blue, bg_red, bg_green, bg_blue) color components.

Each component is in the range 0-255. Values are taken from the XTerm defaults and may not exactly match the user’s terminal.

If the foreground or background is ‘default’ or ‘inherit’ then all their components will be returned as None.

>>> AttrSpec("yellow", "#ccf", colors=88).get_rgb_values()
(255, 255, 0, 205, 205, 255)
>>> AttrSpec("default", "g92").get_rgb_values()
(None, None, None, 238, 238, 238)
Raises:

ValueError – this AttrSpec holds a colour number outside the 88-colour range.

layered_over(outer: AttrSpec, *, colors: Literal[1, 16, 88, 256, 16777216] | None = None) → AttrSpec¶

Return this attribute with its ‘inherit’ colors and its missing hyperlink taken from outer.

An attribute with no ‘inherit’ color is opaque: its colors and settings are kept, and only an underline color or a hyperlink it lacks is taken from outer. With colors given, an opaque attribute also keeps its color mode, and the underline color it takes is parsed in that mode; colors is not used. Otherwise, each setting this attribute turns on (‘bold’) or off (‘no-bold’) is kept, and a setting it does not mention is taken from outer. The result may still inherit a color, when outer inherits it too. The hyperlink is resolved on its own: without one, this attribute takes the hyperlink of outer. The result is a plain AttrSpec whenever it differs from this attribute.

Without colors, every color keeps its kind, so a palette entry stays one beside a 24-bit color, and the result is declared in the mode its colors need. An 88-color entry above 15 that ends up beside a color of another mode becomes its RGB value. With colors, an attribute that is not opaque has each color described as its own color mode names it and parsed in colors, which approximates a color that mode does not have.

Paths:

no 'inherit' color (opaque)
  +- nothing to take from *outer* ------------> this attribute
  +- *colors* None ---------------------------> colors kept by kind, *outer*'s underline color
  +- *colors* given --------------------------> own mode, *outer*'s underline color parsed in it
'inherit' color
  +- *colors* None ---------------------------> channels of both by kind, larger mode
  +- *colors* given --------------------------> descriptions of both parsed in *colors*
Parameters:

  • outer – the enclosing attribute

  • colors – the color mode of a result that is not opaque; None keeps each color as it is, in the larger color mode of the two attributes

Raises:

AttrSpecError – with colors, a color of an attribute that is not opaque, or the underline color an opaque one takes, needs more colors than that result has.

>>> AttrSpec("dark red,bold", "inherit").layered_over(AttrSpec("inherit,underline", "dark blue"))
AttrSpec('dark red,bold,underline', 'dark blue')
>>> AttrSpec("dark red", "default").layered_over(AttrSpec("yellow", "dark blue"))
AttrSpec('dark red', 'default')
>>> AttrSpec("inherit,no-bold", "inherit").layered_over(AttrSpec("yellow,bold,underline", "dark blue"))
AttrSpec('yellow,underline,no-bold', 'dark blue')
>>> AttrSpec("dark red", "default").layered_over(AttrSpec("yellow,bold", "dark blue", hyperlink="https://a.b"))
AttrSpec('dark red', 'default', hyperlink=Hyperlink(uri='https://a.b', id=''))
>>> AttrSpec("h196", "inherit").layered_over(AttrSpec("default", "#102030", 2**24))
AttrSpec('h196', '#102030', colors=16777216)

class urwid.Hyperlink(uri: str, *, id: str = '')¶

Terminal hyperlink (OSC 8) carried by an AttrSpec.

The fields keep the names of the OSC 8 specification. Only printable ASCII is accepted, so a link cannot inject other escape sequences. The URI is limited to 2083 characters and the id to 250: these are urwid’s compatibility limits, taken from the terminals that refuse longer values (VTE and iTerm2 for the URI, VTE for the id). The specification itself sets no limit.

An empty URI is the explicit “no link” state, NO_HYPERLINK: it hides the link of an enclosing attribute.

Parameters:

  • uri – the link target

  • id – groups the cells of one link that the terminal highlights together, when the link is drawn in several separate runs

Raises:

ValueError – uri or id holds a character outside printable ASCII or is too long, id holds : or ;, or id is given with an empty uri.

>>> Hyperlink("https://urwid.org", id="home")
Hyperlink(uri='https://urwid.org', id='home')

class urwid.LayeredAttr(*layers: Hashable)¶

Display attribute made of other display attributes stacked innermost first.

A screen resolves it by placing each layer over the next one with AttrSpec.layered_over(), so a layer whose foreground or background is ‘inherit’ shows the color of the layer under it. Layers are palette names or AttrSpec instances.

Stack layers, innermost first.

A layer that is itself a LayeredAttr is replaced by its layers, None (no attribute) is left out, and a layer repeated next to itself is kept once.

classmethod layer(inner: Hashable, outer: Hashable) → Hashable¶

Return inner placed over outer.

None (no attribute) takes part in no stack: when either is None, inner is returned. The stack is built as the constructor builds it, and a single remaining layer is returned as it is rather than wrapped.

>>> LayeredAttr.layer("red", None)
'red'
>>> LayeredAttr.layer("red", LayeredAttr.layer("bold", "blue_bg"))
LayeredAttr('red', 'bold', 'blue_bg')
>>> LayeredAttr.layer("red", "red")
'red'
